## 이 스킬을 언제 쓰는가

- `calendar_schema.json`의 반복일정 항목 하나를 실제 발행용 콘텐츠(4탭)로 작성할 때
- daylog 외 다른 사이트(apt/trip/pick 등)에서도 같은 반복일정 방식으로 콘텐츠를 만들고 싶을 때 (`site_target` 파라미터로 트리거 구분)
- `daylog_auto_publisher.py`가 자동으로 호출하는 프롬프트 구조를 사람이 수동으로 재현하거나 검토할 때

이 스킬은 `imaboy1212-svg/aptradar`의 `apt_auto_publisher.py` 콘텐츠 파이프라인과 `wp-content-team-article-builder` 스킬의 4탭 구조·규칙을 daylog 반복일정 콘텐츠에 맞게 이식한 것이다.

> **주의**: `wp-content-team-article-builder` 원본 스킬 파일은 이 스킬을 작성한 세션에서 접근 가능한 레포 어디에도 없어서 규칙을 코드로만 유추해 재작성했다. 특히 "이미지 프롬프트 억제 문구"는 원문을 그대로 복사한 것이 아니라 지침(SEO정보 탭에만, 한글로 작성)에 맞춰 새로 만든 문구다. 원본 스킬과 표현이 다르면 원본 기준으로 교체할 것.

## 발행 워크플로 (클로드 코드에서 콘텐츠를 만들 때 — 순서대로, 승인 전에는 워드프레스에 저장하지 않는다)

리드타임 도달 항목의 콘텐츠를 작성할 때는 아래 순서를 지킨다. 워드프레스 크리덴셜이 있어도 코로님 검토 없이 바로 저장하지 않는다.
1. **4탭 대시보드 아티팩트 렌더링** — 코로님이 검토할 수 있게 (artifact-design 스킬 사용). 렌더링 후에는 여기서 멈추고, 코로님의 확인/승인을 기다린다.
2. **코로님이 검토 후 승인하면(같은 대화에서 "저장해줘" 등으로 회신) 그때 워드프레스에 `status=draft`로 저장** — DAYLOG_WP_USERNAME/APP_PASSWORD가 있으면 REST API로 저장. 포커스 키워드는 코로님이 편집기에서 직접 입력하므로 비워두거나 SEO정보 탭 값 그대로 두면 된다.
3. 매일 자동으로 도는 루틴(daylog 반복일정 콘텐츠 자동화)은 1번(렌더링)까지만 하고 종료한다. 2번(워드프레스 저장)은 코로님이 아티팩트를 보고 별도로 요청할 때만 진행한다.

Rank Math 메타(포커스 키워드·메타설명) 자동 업데이트는 아직 확실히 동작하지 않는다 — 일반 `wp/v2/posts` meta 필드로 저장 시도했다가 실패 확인, `POST /rankmath/v1/updateMeta`로 바꿔서도 재시도했지만 애플리케이션 비밀번호 인증으로는 여전히 저장되지 않는 것으로 확인됨(2026-07-22 daylog.bestwellth.org 실제 테스트). 포커스 키워드는 코로님이 편집기에서 직접 입력하기로 했으므로 이 부분은 급하지 않다 — `daylog_auto_publisher.py`의 `wp_update_rank_math` 호출은 best-effort로 남겨두되, 실패해도 무시하고 넘어간다. 대신 본문 자체가 위 체크리스트를 충족하도록 작성하는 데 집중한다.

## site_target 파라미터

반복일정 항목마다 `calendar_schema.json`의 `site_target` 필드로 어느 사이트용 콘텐츠인지 구분한다.

| site_target | 사이트 | 카테고리 프리픽스 세트 |
|---|---|---|
| `daylog` | daylog.bestwellth.org | `[세금·행정마감]` `[명절·기념일]` `[생활·집안일]` `[여행·쇼핑·이벤트]` |
| `apt` | apt.bestwellth.org | 기존 apt_auto_publisher.py 카테고리 체계 사용 (이 스킬 범위 아님) |
| `trip` | trip.bestwellth.org (예정) | 사이트 구축 시 프리픽스 세트 추가 정의 필요 |
| `pick` | pick.bestwellth.org (예정) | 사이트 구축 시 프리픽스 세트 추가 정의 필요 |

`daylog_auto_publisher.py`는 현재 `site_target == "daylog"` 항목만 처리한다. apt/trip/pick 값은 스키마 차원에서만 예약되어 있고, 해당 사이트용 발행 스크립트가 별도로 생기기 전까지는 이 스킬을 사람이 수동으로 참고해 콘텐츠를 만드는 용도로만 쓴다.

## H1 카테고리 프리픽스 규칙

- 본문에는 **H1 태그를 절대 사용하지 않는다.** 본문은 H2부터 시작한다.
- 대신 워드프레스 글 제목(`[TITLE]` 태그) 맨 앞에 카테고리 프리픽스를 텍스트로 붙인다.
- daylog 프리픽스 세트: `[세금·행정마감]` `[명절·기념일]` `[생활·집안일]` `[여행·쇼핑·이벤트]`
  - `세금·행정마감` — 세금 신고·납부, 보험료 납부, 국가건강검진, 인사평가·성과급 등 공식 마감/시점이 있는 항목
  - `명절·기념일` — 설날·추석 등 음력 명절, 발렌타인데이·어버이날·크리스마스 등 상시적 기념일
  - `생활·집안일` — 이사철·방학·개학·계절가전 점검처럼 특정 시기에 몰리는 생활 패턴
  - `여행·쇼핑·이벤트` — 명절/휴가 항공권·기차표·숙소 예약, 블랙프라이데이·광군제 등 세일 시즌, 프로스포츠 개막·카페/뷰티 시즌 프로모션처럼 대중이 미리 챙겨보는 소비·관람·예약 이벤트
- 이 4개는 텍스트 프리픽스일 뿐 아니라 워드프레스에 **실제 카테고리 분류(taxonomy)로도 생성되어 있다** (`wp-admin` > 글 > 카테고리). `daylog_auto_publisher.py`의 `CATEGORY_WP_ID` 딕셔너리가 이름→ID를 매핑하고, `wp_create_draft()`가 글 저장 시 `categories` 필드로 실제 분류를 함께 지정한다. 새 카테고리를 추가하거나 이름을 바꿀 때는 `/wp-json/wp/v2/categories`로 실제 워드프레스 분류도 함께 만들거나 갱신하고 `CATEGORY_WP_ID`를 동기화해야 한다.

## 4탭 대시보드 구조

콘텐츠는 항상 4개 탭에 대응하는 출력을 만든다. `daylog_auto_publisher.py`가 파싱하는 태그 형식을 그대로 따른다.

### 탭 1 — 워드프레스 (본문 HTML)
- `[TITLE]...[/TITLE]` 바로 뒤에 순수 HTML 본문
- 카테고리 뱃지 → 서브 제목(H1 금지) → 핵심 정보 요약 박스 → 목차 → 애드센스 슬롯A → 섹션1 → 애드센스 슬롯B → 섹션2 → 애드센스 슬롯C → 섹션3 → 참고자료+내부링크(있을 때만) → 면책조항 → 애드센스 슬롯D 순서
- 대표 이미지 placeholder 박스는 본문에 넣지 않는다 — SEO정보 탭의 이미지 프롬프트만으로 충분하다는 코로님 지시
- 표는 컬럼 최대 3개, 단문(15자 이하) 셀은 `text-align:center`, 장문 셀은 `text-align:left`, `<th>`는 항상 `text-align:center`
- **형광펜 강조**: 본문이 길어 훑어보기 어려우므로, 각 섹션(본문 3개)마다 가장 중요한 핵심 문장/구절을 1개(최대 2개) `<mark style="background:#fef08a;padding:0 2px;border-radius:2px;">문장</mark>`으로 감싼다. 문장 전체가 아니라 날짜·수치·결론 등 정말 핵심적인 짧은 구절만 감싸고, 표·박스 컴포넌트 내부에는 사용하지 않는다(이미 시각적으로 구분됨) — 본문 `<p>` 문단에만 적용.

#### Rank Math SEO 체크리스트 준수 규칙 (반드시 지킬 것)
포커스 키워드는 코로님이 워드프레스 편집기에서 직접 입력한다(자동화 대상 아님). 대신 콘텐츠 자체가 아래 항목을 이미 만족하고 있어야, 코로님이 키워드만 입력해도 Rank Math 체크가 바로 통과한다.
- SEO 제목 앞부분, 메타 설명, 슬러그(영문), 본문 첫 문단에 포커스 키워드를 그대로 포함
- 본문 전체에서 포커스 키워드(또는 자연스러운 변형)를 반복 — 목표 밀도 약 1%
- 본문 섹션 중 최소 1개의 H2 제목에 포커스 키워드를 그대로 포함
- 대표 이미지 alt 텍스트에 포커스 키워드 포함
- 본문 분량은 최소 600단어(한글 기준 공백 포함 약 1,500자) 이상 — 섹션당 충분히 서술, 요약형으로 짧게 쓰지 않는다
- 목차(각 H2로 점프하는 앵커 링크)와 내부 링크(daylog 홈, `https://daylog.bestwellth.org/`) 최소 1개 포함
- 외부 참고자료 링크 최소 1개 포함

#### 제휴 CTA·애드센스 규칙 (수익화 관련 — 반드시 지킬 것)
- **"클릭해주세요", "광고를 눌러주세요" 같은 클릭 유도 문구는 절대 사용하지 않는다.** 구글 애드센스 정책 위반이며 적발 시 계정 자체가 정지된다(사이트 하나가 아니라 계정 전체).
- 쿠팡/숙박 제휴 CTA 카드는 본문 주제와 실제로 관련된 상품·숙소를 추천할 때만 글당 1개 사용한다. 무관한 글에 억지로 넣지 않는다.
- 제휴 링크의 실제 URL은 알 수 없으므로 절대 지어내지 않는다 — `{COUPANG_AFFILIATE_LINK}` / `{ACCOMMODATION_AFFILIATE_LINK}` placeholder를 그대로 두고, 코로님이 발행 전 실제 링크로 교체한다.
- daylog 애드센스 승인 완료 — 아래 4개 슬롯은 실제 광고 코드(`ca-pub-6858780475640766`)이므로 값을 임의로 바꾸지 않고 그대로 사용한다:

  - **슬롯 B (가로형 인피드, slot 5165217836)** — 첫 번째 섹션(소주제) 바로 아래
  - **슬롯 C (인아티클 플루이드, slot 8908458700)** — 두 번째 섹션(소주제) 바로 아래
  - **슬롯 D (오토릴렉스드, slot 3873632172)** — 면책조항 바로 아래, 글의 맨 마지막

### 탭 2 — 미리보기
- 별도 태그 없음. 탭 1의 HTML을 워드프레스 에디터/프리뷰에서 그대로 렌더링해 확인하는 탭이다. 콘텐츠 생성 시 별도 작업 불필요.

### 탭 3 — SEO정보
아래 태그를 모두 채운다:
- `[FOCUS_KW]` — 3~4단어 롱테일 키워드 (워드프레스 심화 파트 기준)
- `[META_DESC]` — 130~155자 문장형 메타 설명 (해시태그·버튼텍스트 금지)
- `[SLUG]` — 영문 슬러그 (한글 감지 시 `id-연도` 형식으로 자동 대체됨)
- `[EXCERPT]` — 100~150자 발췌문
- `[HASHTAGS]` — 검색·공유용 해시태그 5개, `#태그1 #태그2 #태그3 #태그4 #태그5` 형식. 본문에는 넣지 않고 이 태그로만 출력
- **이미지 프롬프트 공통 규칙 (아래 `IMAGE_PROMPT_*` 태그 전부에 적용):** 독자 대부분이 국내(한국) 이용자이므로, 이미지 안에 렌더링되는 모든 텍스트(제목·부제·라벨 등)는 브랜드명 등 고유명사를 제외하면 **거의 전부 한글로 표기**해야 한다는 문장을 프롬프트에 명시적으로 포함한다. 영문 단어(예: "VAT", "Tax")가 이미지에 렌더링되지 않도록 "이미지 내 텍스트는 고유명사를 제외하고 모두 한글로 표기, 영문 사용 금지"라는 취지의 문장을 프롬프트 끝에 반드시 넣는다.
- `[IMAGE_PROMPT_NAVER_1_1]` / `[IMAGE_PROMPT_WP_16_9]` — **한글로 작성하는 카드뉴스형 이미지 프롬프트 2개.** 이 탭에만 배치하고 본문에는 절대 노출하지 않는다.
  - `NAVER_1_1`은 네이버 카드뉴스용 1:1 정사각형, `WP_16_9`는 워드프레스 대표이미지용 16:9 가로형
  - **제목 출처가 서로 다르다:** `NAVER_1_1`의 대제목·부제는 탭4의 `[NAVER_TITLE]`(넓은 개요 키워드) 문구를 기반으로 하고, `WP_16_9`의 대제목·부제는 탭1의 `[TITLE]`(심화 파트 포커스 키워드) 문구를 기반으로 한다 — 둘을 같은 문구로 재사용하지 않는다.
  - 스타일: 아이콘·색상 블록 위주의 추상적 인포그래픽이 아니라 **실사 사진 또는 고퀄리티 애니메이션(일러스트) 스타일** — 주제를 한눈에 알아볼 수 있는 구체적인 장면(인물·사물·장소)을 중앙에 크게 배치
  - 구성: 배경 위에 반투명 단색 컬러 오버레이를 입혀 글자 가독성 확보 → 화면 중앙에 각자의 제목(대제목)과 부제(부제목) 텍스트를 큼직하게 배치
  - 텍스트 렌더링: 실제로 들어갈 제목·부제 문구를 프롬프트에 그대로 포함해 이미지 생성기가 렌더링하도록 요청한다. **텍스트 정확도에 대한 제약은 없다** (이전처럼 "정확한 한글 텍스트 렌더링 요청 금지" 문구를 넣지 않는다).
  - 억제 문구: 이미지 안에 주제·부제 텍스트는 넣어야 하므로 "텍스트 없이" 문구는 넣지 않는다. 다만 "워터마크·로고·특정 브랜드/실존 인물 식별 불가하도록" 문구는 저작권 문제 방지를 위해 계속 유지한다.
- `[IMAGE_PROMPT_SUBTOPIC_N]` (N=1,2,3...) — **네이버블로그 탭(탭4) 본론 소주제별 인포그래픽 이미지 프롬프트.** 소주제 개수(2~3개)와 정확히 같은 개수만큼 출력한다. 이 탭에만 배치한다.
  - 위 대표 이미지 2개와 스타일이 다르다 — 실사·애니메이션이 아니라 **인포그래픽 방식**(아이콘, 색상 블록, 체크리스트, 막대·화살표 데이터 시각화, 짧은 텍스트 라벨)으로 작성한다.
  - 각 프롬프트는 해당 소주제 본문 내용의 핵심 정보(날짜·대상·체크리스트·수치 등)를 반영해서 구성한다.
  - 1:1 정사각형, 실제 라벨 문구를 그대로 포함해 렌더링 요청(텍스트 정확도 제약 없음), 워터마크·로고·특정 브랜드/실존 인물 식별 요소 금지는 동일하게 적용한다.

### 탭 4 — 네이버블로그
- `[NAVER_TITLE]` — 네이버블로그 전용 제목. **워드프레스 `[TITLE]`과 반드시 다른 문구로 작성한다.** 워드프레스 제목이 심화 파트의 좁고 구체적인 키워드(예: "부가가치세 계산법")를 노린다면, 네이버 제목은 이 이벤트의 넓은 개요 키워드(예: "부가가치세 확정신고 기간과 대상")를 노린다. 카테고리 접두어(`[세금·행정마감]` 등)는 붙이지 않는다 — 네이버는 워드프레스와 별개 채널이라 워드프레스 카테고리 체계를 노출할 필요가 없다.
- `[NAVER_SUMMARY]` — 900~1200자, 순수 텍스트(HTML 태그 없음), 격식 경어체(합니다/습니다체)
- 이 이벤트의 **전체 개요(총론)**를 다룬다 — 워드프레스 탭 1은 같은 주제를 더 심층적으로 다루는 파생 글이라 역할이 다르다 (아래 "네이버 ↔ 워드프레스 관계" 참고)
- **반드시 서론-본론-결론 3단 구조로 작성한다:**
  - 서론: 주제 소개 + 오늘 다룰 내용 예고 + "구체적인 [워드프레스 심화 주제]는 블로그에서 이어서 다룬다"는 문장으로 워드프레스와 자연스럽게 연동
  - 본론: 소주제 2~3개. 각 소주제는 "①/②/③ 소주제 제목"을 한 줄로 적고 그 아래 본문 내용을 문단으로 서술 — 소주제 제목과 본문 내용을 명확히 구분한다
  - 결론: 본론 요약 + 워드프레스로 연결되는 CTA 문장 + 마지막 줄에 "▶ [워드프레스 글 링크]"(실제 URL은 발행 후 코로님이 직접 채워 넣음 — 지어내지 않는다)
- 실제 네이버 게시는 자동화하지 않는다 — 텔레그램 알림에 포함된 개요를 코로님이 복사해서 수동으로 올린다

## 네이버 ↔ 워드프레스 관계 (콘텐츠 중복 방지)

같은 주제를 다루되 같은 내용을 요약해서 두 채널에 중복 게재하지 않는다. 역할을 분리한다.

1. **네이버블로그(탭4)** = 이 이벤트의 전체 개요(총론). 서론-본론(소주제 2~3개)-결론 구조로 언제·대상·무엇을·어떻게를 폭넓게 다룬다. 넓은 키워드(예: "재산세 납부기간")를 노린다.
2. **워드프레스(탭1)** = 네이버 개요 중 **깊이 있게 파고들 가치가 있는 한 파트**(계산 방식, 조건별 차이, 자격 기준 등 구체적 수치·표가 필요한 부분)만 골라 집중적으로 확장한 파생 글(심층). 네이버 글 전체를 다시 요약하지 않는다. 좁고 구체적인 키워드(예: "재산세 계산법")를 노린다.
3. 두 글이 시리즈처럼 느껴지도록 자연스러운 연결 문구를 넣는다 — 네이버 글의 서론과 결론 모두에 워드프레스 연동 문구를 넣고, 워드프레스 글 도입부에는 "~에 이어 이번에는 ~를 자세히 살펴봅니다" 같은 문장.
4. 워드프레스 심화 파트에서 매년 바뀌는 구체적 수치(세율·비율 등)는 단정하지 말고, 안정적으로 알려진 구조(공식·산정 방식·표준 기준표)를 중심으로 설명한다. 연도별로 조정되는 값은 "공식 사이트에서 확인" 처리한다.

## 공통 확정 규칙 (변경 금지)

- 한국 주식시장 상승=빨강, 하락=파랑 (daylog 콘텐츠에는 보통 해당 없음, apt 등 타 사이트 재사용 시 유지)
- 본문에는 H1 태그 사용 금지, H2부터 시작
- 이미지 프롬프트는 SEO정보 탭에만 배치, 한글로 작성
- 표 정렬: 단문(15자 이하) center, 장문 left, th는 항상 center
- 네이버 블로그 요약은 900~1200자, 격식 경어체, 순수 텍스트(HTML 없음), 서론-본론(소주제 2~3개)-결론 구조

## audience(타겟 독자층) 참고

`calendar_schema.json`의 `audience` 필드(`직장인`/`부모`/`주부`/`전체`)는 본문 톤과 관점을 정하는 데 쓴다. 예를 들어 `부모` 대상 항목은 "우리 아이"를 주어로 한 조언 톤을, `직장인` 대상 항목은 "실무자/근로자" 관점의 팩트 중심 톤을 사용한다.
